# Rodar um job de novo cria uma nova tentativa

`POST /assets/{id}/jobs` com `{"type": ...}` cria uma nova linha em `processing_jobs` para aquele tipo, em vez de reabrir a linha antiga. Assim o histórico de tentativas, com logs e erros de cada uma, continua visível no dashboard. Só é permitido quando nenhum job do asset está `pending` ou `running`, e a verificação trava a linha do asset para dois pedidos simultâneos não criarem duas tentativas. Roda só o job pedido: o pipeline não continua para os passos seguintes, porque quem pede uma nova miniatura não quer reconverter o vídeo. Rodar o `transcode-hls` de novo devolve o asset para `processing` até o fim do job, coerente com a ADR 0003. A alternativa de reabrir a mesma linha seria mais simples, mas apagaria o motivo da falha anterior — justamente o que se quer investigar.
