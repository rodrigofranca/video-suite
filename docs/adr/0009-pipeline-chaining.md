# A API cria todos os jobs do upload e o worker encadeia os próximos

No upload, a API cria as três linhas de job (`extract-metadata`, `generate-thumbnail`, `transcode-hls`) como `pending` e coloca só a primeira na fila. Quando um job termina, com sucesso ou com falha, o worker coloca na fila o próximo job pendente do mesmo asset; a ordem vem de `jobcontracts.Pipeline`. A alternativa — enfileirar os três de uma vez — rodaria a miniatura sem conhecer a duração do vídeo (que o job de metadata vai extrair) e, com mais de um worker, os jobs do mesmo asset rodariam fora de ordem. Criar as linhas logo no upload faz o painel mostrar o pipeline inteiro desde o início. Falhas em metadata e thumbnail não interrompem a cadeia (ADR 0003). Se o próximo job não puder ser enfileirado, ele e o asset são marcados como `failed`, para nada ficar parado em `processing` sem explicação. Uma entrega duplicada de um job já concluído não roda de novo; só confere se o próximo passo foi enfileirado.
