# Modelos de linguagem pelo gateway LiteLLM, com o OpenCode como primeiro provedor

Os serviços da plataforma não falam com provedores de modelos de linguagem: falam com um gateway LiteLLM, pela API de chat completions da OpenAI, usando nomes de modelo definidos no gateway (`ultramedia-text`). O provedor, o ID do modelo e a chave existem só em `infra/litellm/config.yaml` e no ambiente do gateway; o worker de IA conhece apenas `LLM_BASE_URL`, `LLM_API_KEY` e `LLM_MODEL`. Assim, trocar de modelo ou de provedor, comparar preços ou ter um modelo reserva é mudar um arquivo, sem mexer em código. O primeiro provedor é o OpenCode Zen, pago por uso, pelo endpoint compatível com a OpenAI (`https://opencode.ai/inference/openai/v1`). O modelo padrão é o Claude Haiku 5.5: US$ 0,10 por milhão de tokens de entrada e US$ 0,50 de saída, o mesmo preço da Anthropic (o Zen cobra só uma taxa por recarga), menos de US$ 0,001 por vídeo de 10 minutos (medido: US$ 0,0005 num vídeo de 2 minutos, com resumo, 7 tags e 6 capítulos). Testado em 2026-11-07: o OpenCode Go não serve, porque é feito para agentes de código e exige cabeçalhos de sessão deles, e os modelos grátis só funcionam dentro do OpenCode. Quando o volume justificar, uma chave direta da Anthropic dá o mesmo preço sem a taxa e com desconto em lote, mudando só a configuração do gateway.

Localmente, o gateway roda no Compose, publicado só em `127.0.0.1:4000` por guardar a chave do provedor, e só com a chave mestra. O plano é rodá-lo num VPS (Hetzner ou outro barato) que atende vários projetos, cada um em seu servidor e falando com o gateway por rede privada. Lá, cada projeto deve ter sua chave virtual, o que exige o banco do LiteLLM. Se o próprio OpenCode for ligado ao gateway, como na opção "Connect Provider → LiteLLM" do console dele, o gateway precisa de endereço público com HTTPS e uma chave só para isso. Esses pontos ficam para a entrega do VPS.

A versão 1.107.0 do LiteLLM (21/10/2026) foi publicada com um ladrão de credenciais, no PyPI e nas tags `latest`/`main-stable` das imagens. Por isso a imagem é fixada pelo digest da 1.108.2 (LTS), com assinatura conferida pela chave cosign que o projeto passou a usar depois do incidente. Atualizar exige escolher outro digest e conferir a assinatura de novo; nunca usar uma tag flutuante. O gateway também usa a tabela de preços que vem na imagem (`LITELLM_LOCAL_MODEL_COST_MAP`), em vez de baixá-la da branch `main` do GitHub a cada início, e roda com a telemetria desligada.
